# Token 规则模板

把下面这段放进 `AGENTS.md`，或按需裁剪。目标是让模型在被审计时少犯这些错。

```markdown
## Token 纪律

- 先读索引再读文件：全局 `memory/INDEX.md` → 工作区 `INDEX.md` → 那一个主题文件。不整库读。
- 读文件先用 grep 定位，再 read 指定区间；不整篇读超过 500 行的文件。
- 工具输出先落盘，只把结论和关键行带进上下文；shell 输出加 head/limit。
- 同一路径不读第二遍；需要复查时用 offset/limit 读那一段。
- 到阶段边界就压缩：已完成阶段的细节、死路、重复日志都压成结论。
- 长任务拆会话；一个会话不跨「调研 → 实现 → 交付」三个阶段。
- 工具集只留当前任务需要的；不用的工具从配置里去掉，别让 schema 每步都跟着。
- 简单任务降 reasoning effort；只有真需要权衡时才开高推理。
- 稳定内容放最前（system、工具定义、项目约定），动态内容放最后，保住前缀缓存。
```

配套检查：

```bash
agh-lite audit --days 7 --out runs/audit.md
```

看三个数：平均每步 prompt、工具 schema、缓存命中率。
